# Project Structure And Cleanup

Last reviewed: 2026-09-04.

## Canonical Structure

```text
app/                 Laravel domain and application code
bootstrap/           Laravel bootstrap; generated cache is not source
config/              Framework and service configuration
database/            Migrations, factories, and seeders
deploy/              Provisioning and exceptional deployment workflows
docker/              Production containers and the canonical deploy scripts
docs/                Maintained runbooks, legal text, exports, and audit notes
public/              Web root; public/build is generated by Vite
resources/           Vue source, Blade views, CSS, and source assets
routes/              HTTP, API, console, and broadcast routes
scripts/             Admin, development, export, health, maintenance, and quality tools
storage/             Local/runtime data; never treat as source
tests/               PHPUnit and Vitest suites
```

The repository root should contain only framework entrypoints, dependency
manifests, tool configuration, the primary Docker files, README, security and
license/notice documents. One-off deployment, diagnosis, and incident files do
not belong in the root.

## Deployment Ownership

- `docker/scripts/deploy.sh` is the deployment entrypoint used by README and CI.
- `docker/scripts/setup-server.sh` provisions the standard Docker host.
- `deploy/new-server/` contains first-server provisioning and its runbook.
- `deploy/admin/` contains bounded administrative repair utilities.
- `deploy/legacy/` remains only for compatibility with still-referenced manual
  release paths; retire it after a verified replacement release.

## Deliberately Retained

- `output/local-backups/`: two local SQLite backups; deleting backups requires a
  separate retention decision.
- `storage/logs/`: application evidence that may need sensitive-data review and
  an explicit retention policy.
- `database/database.sqlite`: the active local database.
- `node_modules/` and `vendor/`: generated dependencies, but required for the
  current local development environment and reproducible verification.
- `public/build/`: generated output currently used for production-like local
  serving; it remains ignored by Git.
- Duplicate bank images under `public/images/banks/` and
  `resources/images/logo/banks/`: both paths are actively consumed by Blade/PDF
  rendering and Vite components respectively.

## Guardrails

- New temporary browser artifacts belong under ignored output locations.
- New operational scripts must live under the matching `scripts/` or `deploy/`
  category and must not embed credentials or fixed server addresses.
- Documentation should link to `docs/deployment/DEPLOYMENT.md` as the canonical
  deployment guide.
- CI should call package scripts (`npm run budget`, `npm run deps:health`) rather
  than duplicate internal file paths.
